# Authenticated limiter-pressure evidence

The local subscription gRPC `GetSubscription` endpoint supports an optional request metadata field `elx-pressure-challenge` containing exactly 32 lowercase hexadecimal digits generated by Control (16 unpredictable bytes). The response metadata includes `elx-pressure-bin`, containing 120 bytes of signed data followed by a 64-byte Ed25519 signature. The endpoint is restricted to loopback or a protected Unix socket; the existing remote usage agent must relay evidence only through mTLS.

The signed data is fixed-width big-endian:

| Offset | Length | Meaning |
| --- | --- | --- |
| 0 | 16 | Running core incarnation UUID |
| 16 | 8 | Per-subscription monotonic sequence (shared with usage) |
| 24 | 8 | Unix time in nanoseconds |
| 32 | 8 | Persisted subscription policy revision |
| 40 | 8 | Current upload bytes/second |
| 48 | 8 | Current download bytes/second |
| 56 | 8 | Upload accepted payload bytes |
| 64 | 8 | Upload token-blocked calls |
| 72 | 8 | Upload token-blocked duration in nanoseconds |
| 80 | 8 | Upload currently blocked calls |
| 88 | 8 | Download accepted payload bytes |
| 96 | 8 | Download token-blocked calls |
| 104 | 8 | Download token-blocked duration in nanoseconds |
| 112 | 8 | Download currently blocked calls |
| 120 | 64 | Ed25519 signature |

Domain-separated signature transcript:

```
elx-pressure-v1
<lowercase-hex-encoded UTF-8 challenge text>
<lowercase-hex-encoded UTF-8 subscription ID>
<lowercase-hex-encoded 120 evidence bytes>
```

The real transcript consists of these three newline-separated values prefixed by the literal `elx-pressure-v1`. The signature is generated **only** by the durable core signing key. Missing/corrupt policy state fails closed.

The counters are cumulative within the core process; the gauge is instantaneous. A signed report proves what the pinned core measured, **not** that it is still the assigned owner of the node/resource, that its lease is valid, or that it is entitled to additional speed. Control must validate the mTLS node identity, pinned incarnation/key, present policy revision, strictly increasing sequence, timestamp freshness, and the source's assigned node/resource before using the counters.

The legacy `elx-usage-bin` transcript used by FUP accounting remains unchanged. The pressure report is strictly separate and cannot be counted as new billable traffic by itself. A remote receiver, durable pressure high-watermark and policy-aware demand estimator must be wired before enabling automated cross-node reallocation.
